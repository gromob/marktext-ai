# 로컬 AI 연결과 설정

이 문서는 `v0.21.2-ai.2`를 기준으로 개발한 로컬 변경을 설명한다. 새 공개 릴리스의 버전·태그는 아직 정하지 않았다. [기준 프로젝트](https://github.com/yunju-baek/marktext-ai)와 [개선 작업 저장소](https://github.com/gromob/marktext-ai)를 구분하며, 기준 공개 설치판에는 아래 변경이 포함되지 않는다.

## 연결 선택

AI 창 위쪽에서 **Codex / 로컬 AI**를 선택한다. Codex는 기존 CLI 로그인과 모델 선택을 사용한다. 로컬 AI는 OpenAI 호환 서버에 연결하며 서버 실행·종료와 모델 로딩·교체는 사용자가 담당한다.

로컬 모델을 선택하면 해당 서버의 저장된 주소와 키를 사용한다. 서로 다른 서버가 같은 모델 ID를 제공해도 별도 항목으로 구분한다. 연결·인증·모델 오류가 발생해도 다른 서버나 Codex로 자동 전환하지 않는다.

## 서버와 모델 등록

1. **로컬 AI → 서버·모델 관리**를 연다.
2. 기존 서버 또는 **새 서버**를 선택하고 서버 이름·주소·필요한 API 키를 입력한다. 루트 주소만 입력하면 `/v1`을 붙인다. 다른 컴퓨터의 서버에는 그 컴퓨터의 주소를 입력한다. `127.0.0.1`은 앱이 실행되는 Mac 자신을 가리킨다.
3. **모델 목록 조회**를 누른다. 변경한 주소·이름·키를 먼저 저장한 뒤 조회한다. **저장된 주소** 표시로 실제 저장값을 확인한다. 키 아래 **서버 설정 저장**으로 따로 저장할 수도 있다. 미완성 모델 입력 행이 있어도 서버 설정은 먼저 저장할 수 있다.
4. 조회한 모델 옆 **등록**을 누르거나 **모델 직접 추가**에서 정확한 모델 ID와 표시 이름을 입력한다. 모델 ID는 따옴표 없이 서버가 제공한 대소문자·슬래시·하이픈을 그대로 입력한다.
5. **서버·모델 저장 → 관리 닫기** 후 AI 입력창 아래의 모델 메뉴에서 사용할 모델을 직접 선택한다.

기본 프로필은 다음과 같다. 실제 서버가 해당 주소에서 실행되고 모델을 제공해야 한다.

| 프로필 | 기본 서버 주소             | 모델 ID                          |
| ------ | -------------------------- | -------------------------------- |
| Strata | `http://127.0.0.1:8081/v1` | `qwen3.8-flash-next-iq3_xxs`     |
| Splash | `http://127.0.0.1:8007/v1` | `mlx-community/Qwen3.8-27B-4bit` |

원격 Strata 서버의 실제 주소와 개인 API 키는 코드에 포함하지 않는다. Splash에는 제공된 공개 기본 인증값 `local`을 사용하며 설정에서 교체하거나 삭제할 수 있다.

## 수정과 삭제

등록한 서버 이름·주소·키와 모델 ID·표시 이름을 관리 화면에서 수정할 수 있다. 모델 옆 **삭제**를 누른 뒤 저장하면 선택 메뉴에서도 제거된다. **서버 삭제 → 삭제 확인**은 해당 서버의 등록 모델과 저장된 키를 함께 삭제한다. 사용 중인 선택을 삭제하면 전송을 막고 다른 모델을 직접 선택하게 한다.

이전 설정의 자동 모델 조회는 해당 서버를 관리 화면에서 저장하기 전까지 유지한다. 관리 화면에 저장한 이후에는 등록한 모델만 선택 메뉴에 표시하며, 삭제한 항목을 서버 조회 결과로 되살리지 않는다. 등록 모델이라도 서버의 `/models` 응답에 없으면 전송할 수 없다. 연결에 실패한 항목은 설정을 수정하기 위해 선택할 수 있지만 요청은 보낼 수 없다.

서버는 최대 20개, 서버당 등록 모델은 최대 200개다. AI 요청 중에는 연결과 서버 설정 변경을 차단한다. 현재 모델의 주소·키만 바꾸는 **연결 설정**도 제공한다.

## API 키 저장

로컬 서버용 키는 이 컴퓨터의 앱 프로필 `ai-connection.json`에 **평문으로 저장**한다. 개인 로컬 서버 토큰에 키체인이 필요하지 않다는 사용자 요구에 따른 설계다. 로컬 AI 키 저장·읽기에서는 키체인을 호출하지 않는다. Codex의 인증 저장 방식은 변경하지 않는다.

키 입력란은 비밀번호 형식으로 표시하고 저장된 값을 다시 채우지 않는다. 메인 프로세스의 설정 조회 응답에는 키 존재 여부만 반환한다. 사용자의 실제 키는 브라우저 localStorage, 배포 설치판 또는 소스에 넣지 않는다. 실제 키 문자열을 입력해야 하며 OpenCode의 `{file:...}` 참조 문법이나 인증 파일 자동 읽기는 지원하지 않는다.

빈 키 입력은 기존 값을 유지한다. **저장된 키 삭제**를 선택하면 지운다. 이전 버전에서 암호화한 키는 자동으로 해제하거나 삭제하지 않으며, 사용자가 한 번 다시 입력해 저장해야 한다. 새 키를 저장하면 해당 서버의 이전 암호화값을 교체한다. 서버 주소·이름·모델 목록은 보존한다.

## 대화와 문서 편집

인사·질문은 Markdown을 변경하지 않고 채팅으로 답한다. 문서 수정 요청은 검증된 결과를 한 번의 편집 작업으로 적용한다. 채팅의 **되돌리기** 또는 편집기의 실행 취소를 사용할 수 있다. 요청을 기다리는 동안 문서나 탭이 바뀌면 오래된 결과를 적용하지 않는다.

요청 시 현재 문서 전체와 최근 대화가 선택한 서버로 전달된다. 질문 모드는 모델별 문맥 예산 안에서 대화를 누적하고, 편집 모드는 최근 10개·24,000자(메시지당 8,000자)를 전달한다. 앱 전송 상한은 질문 본문 2,000,000자·대화 8,000,000자·10,000개 메시지이며, 실제 입력은 더 작은 모델 문맥 예산을 따른다. 편집 본문은 300,000자, 이번 요청은 두 모드 모두 8,000자까지다. 대화와 작성 중인 요청은 실행 중인 창에서 문서별로 유지된다.

OpenAI 호환 `GET /v1/models`와 `POST /v1/chat/completions`를 사용한다. 비스트리밍 JSON 모드(`response_format: json_object`)를 요청하며, 완전한 Markdown과 짧은 답변을 포함한 응답을 검증한다. 잘못된 JSON·출력 잘림·과도한 응답은 문서에 적용하지 않는다. 리디렉션에는 인증 헤더를 전달하지 않는다. 모델 조회는 15초, 로컬 응답은 기본 10분까지 기다리며 모델별로 60–3600초로 설정한다. Codex의 기존 3분 제한은 유지한다.

현재 연결은 텍스트 대화와 Markdown 편집용이다. 이미지·PDF 첨부나 도구 실행 기능은 포함하지 않는다.

## AI 창 글꼴 크기

AI 창의 **A− / A+**와 **Preferences → Editor → AI 창 글꼴 크기**는 같은 설정을 사용한다. 기본 13px이며 12–24px로 조절한다. 대화·입력창·연결 및 모델 메뉴·서버 관리 화면에 함께 적용하고, 제목·보조 안내의 상대적인 크기 차이는 유지한다.

본문 편집기 글꼴 크기와는 별도로 저장하며 열린 창에 즉시 반영하고 다음 실행에도 유지한다. 렌더러 상수는 `src/shared/aiTypography.ts`, 영속화 검증과 기본값은 `src/main/preferences/schema.json`과 `static/preference.json`에 있다.

## 문서 질문과 응답 대기

**질문·분석** 모드에서는 모델이 답변(`summary`)만 반환하도록 요청하고 앱은 본문 변경을 차단한다. **문서 편집** 모드에서는 완성된 수정 본문과 변경 설명을 받는다. Codex와 모든 로컬 서버에 같은 모드 구분을 적용한다. AI 입력창에서 **Shift+Tab** 또는 모드 버튼으로 전환하며 기본은 질문·분석이다. 이전 모드 없는 요청의 `markdown: null` 응답도 호환 처리한다. 입력에는 여전히 현재 문서와 최근 대화를 전달한다.

로컬 응답 대기는 기본 10분이며 모델별 대기 시간 설정을 따른다. 모델 목록 조회는 15초다. 시간 초과는 문서 분량 초과와 다르다. 서버에서 입력 처리나 생성이 진행 중인지, 요청이 대기열에 있는지 확인한다. 앱의 자동 검사와 실제 서버·모델의 응답 속도 검증은 구분한다.

2026-10-25 수정 검사: 관련 단위 검사 28개, Electron E2E 8개, 타입 검사와 변경 파일 ESLint가 통과했다. 큰 한글 문서의 원문 보존과 두 로컬 연결의 `markdown: null` 응답을 검사했다. macOS arm64 앱·ZIP·DMG 빌드와 서명·DMG 무결성 검사도 통과했다. 실제 Strata·Splash 서버에서 사용자가 보고한 시간 초과의 해소 여부는 아직 확인하지 않았다.

### 명시적 모드 검증 (2026-10-25)

질문·분석을 기본으로 하고 버튼과 AI 입력창 Shift+Tab으로 문서 편집과 전환한다. Codex는 질문용 답변 전용 스키마를 사용하고 로컬 AI도 답변만 요청한다. 두 백엔드와 화면 모두 질문 모드에서 반환된 수정 본문을 적용하지 않는다. 요청 모드는 전송 시 고정하며 처리 중 전환은 막는다. 서버 관리 중에는 작성 내용을 유지한 채 입력창을 숨겨 저장 버튼 공간을 확보한다.

관련 단위 검사 32개와 Electron E2E 15개가 통과했다. 타입 검사·변경 파일 ESLint, macOS arm64 앱·ZIP·DMG 빌드 및 무결성 검사도 통과했다. 합성 한글 조합 이벤트 중 Shift+Tab 전환 시 동일한 입력 요소·문자열·선택 영역·포커스 유지를 검사했다. 실제 macOS 입력기와 Strata·Splash 추론 속도는 사용자 확인이 필요하다.

## 질문 문맥과 새 대화

질문 모드는 고정 지침 → 기준 문서 → 누적 대화 → 새 질문 순서로 전송한다. 같은 모델·문서에서는 앞부분이 유지되어 서버의 접두부 캐시를 재사용하기 쉬운 구조다. 실제 캐시 사용과 속도 향상은 서버 지원·설정에 달려 있으며 앱에서 보장하거나 강제하지 않는다. 문서가 바뀌거나 오래된 대화를 제외하면 재사용 범위가 줄어든다.

`/models`의 실제 문맥 정보(`meta.n_ctx`, `context_length`, `max_model_len`)를 읽고, 등록 모델의 문맥 설정이 있으면 그 값을 우선한다. 학습 최대값 `n_ctx_train`을 실행 중 한도로 간주하지 않는다. 2026-10-26 모델 목록 조회에서 Strata는 131072, Splash는 262144를 보고했다. 모델이나 서버 설정이 바뀌면 값도 달라질 수 있다.

서버·모델 관리의 각 모델에 문맥 한도, 질문 출력·추론 예산, 대기 시간을 설정한다. 문맥을 모르면 8192토큰을 기본값으로 사용하며 화면에 미확인이라고 표시한다. 기본 출력 예약은 문맥의 1/4과 4096 중 작은 값이다. UTF-8 바이트 수를 보수적인 토큰 추정치로 사용하고 채팅 템플릿 여유 1024토큰도 남긴다. 정확한 모델 토크나이저 계산은 아니므로 실제 최대량보다 적게 들어갈 수 있다. 모델에 할당된 토큰을 초과하지 않도록 출력·추론 공간을 남긴다.

예산이 부족하면 문서와 새 질문은 유지하고 오래된 대화 메시지부터 통째로 제외한다. 제외 개수를 응답 뒤에 표시하며, 화면의 전체 대화 자체를 삭제하지 않는다. 문서와 질문만으로 예산을 넘으면 자동으로 문서를 자르지 않고 요청을 막는다. 질문 답변은 최대 128000자까지 받되 실제 출력은 설정된 출력 예산에 따른다.

입력창에 정확히 `/new`를 입력하고 Enter를 누르거나 **새 대화**를 누르면 현재 문서의 대화·작성 중 입력을 비운다. 문서·모델·모드·서버 설정은 유지하고 서버에는 초기화 명령을 보내지 않는다. 다른 문서의 대화와 서버 KV 캐시는 초기화하지 않는다. 요청 처리 중에는 초기화를 막으며 취소 후 사용할 수 있다.

로컬 응답 대기는 기본 600초이며 모델별로 60–3600초를 저장할 수 있다. 입력창 위에 현재 문맥·출력 예약·대기 시간과 처리 중 경과 시간을 표시한다. Codex 질문도 보수적 기본 문맥 예산으로 제한하지만 현재 로컬 모델 관리 설정은 Codex에는 적용하지 않는다. 스트리밍은 이번 변경 범위에 포함하지 않았다.

### 문맥·초기화 검사 (2026-10-26)

관련 단위 검사 59개, Electron E2E 17개가 통과했다. 모델 문맥 메타데이터 읽기·설정 우선순위·큰 대화 유지·예산 초과 시 원문 보호·오래된 메시지 제외·입력 접두부 유지·모델별 대기 시간·설정 저장·`/new`·새 대화·경과 시간·취소를 검사했다. 실제 서버에서는 모델 목록만 조회했으며 추론이나 캐시 속도 측정은 하지 않았다. 정확한 토큰 계산과 스트리밍은 지원하지 않는다.
